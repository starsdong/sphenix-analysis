\paragraph{Skims and the analysed samples.}
\begin{itemize}
\item \textbf{10\% skim}: \tenFiles{} production files, \tenIn{} $\to$ \tenOut{} candidates (\tenFrac\%), local copy
  \fpath{../ntuples/d0skim/D0skim_prod10pct_*.root} (5 files). Used for Secs.~\ref{sec:pid}--\ref{sec:trial} and the
  10\% part of Sec.~\ref{sec:ratio}.
\item \textbf{Full skim}: all \fullFiles{} \Dzero{} files of both productions, \fullIn{} $\to$ \fullOut{} candidates
  (\fullFrac\%), \fullJobsOK{} condor jobs OK, \fullJobsFailed{} failed (cluster 480615), 13\,GB on SDCC in
  \fpath{output/d0skim_full/}.
\item \textbf{Full $\pt$ skim}: the full skim with \Dzero{} $\pt>1.5\gevc$, \tightIn{} $\to$ \tightOut{} candidates
  (\tightFrac\%), local copy \fpath{../ntuples/d0tight_full/D0tight_pT1p5_run*.root} (4 files, md5 in
  \fpath{logs/local_files_md5.txt}). Used for the full-sample part of Sec.~\ref{sec:ratio}. The DIRA range 0.95--0.98 is
  kept for the ratio control.
\end{itemize}

\paragraph{Mass hypothesis and charge.} In both analysed samples track~1 carries the pion and track~2 the kaon
hypothesis (\hypFracTen\% and \hypFracFull\%), and each track pair appears once (\multiTen{} and \multiFull{} pairs stored
more than once; \fpath{logs/inputs.txt}). The \fcmd{D0_PDG_ID} branch is $+421$ for every candidate, so \Dzero{} and
$\bar{\mathrm{D}}^0$ are distinguished only by the charge of the kaon-hypothesis track; they are not separated here.

\caveat{KFParticle keeps one $K\leftrightarrow\pi$ assignment per track pair (the production macro notes it is chosen by
the PV-DCA $\chi^2$, not by PID; not re-checked in the KFParticle source for this note). A true \Dzero{} whose pair was
given the wrong assignment is stored at a shifted, broadened mass and is missing from the narrow peak. The fraction is
unknown without simulation (open issue~1). The swapped mass can be recomputed offline from the stored daughter momenta;
this is not done in this note (open issue~3).}

\caveat{The 10\% production files do not contain the processed-event count (added later for the 90\% production), so the
number of events of the 10\% skim is not given; results here are not normalised per event.}
